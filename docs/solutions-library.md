# Решения производителей

Раздел `/solutions/` отделён от каталога поставки, производителей и партнёров.
В реестре 7 брендов и 30 материалов: Eltex, YADRO, ISS, Астро-Лифт, BLT,
Saint-Gobain и ISTKULT. Карточки других производителей появляются после добавления
реальных презентаций.

## Источник данных и пополнение

`data_import/solutions.json` — единый реестр производителей, описаний и PDF.
Для нового производителя добавьте slug, имя, существующий официальный логотип,
описание и documents. Для документа укажите уникальный slug, отрасль, описание,
краткую проверенную аннотацию, количество страниц, относительные static-пути
PDF/обложки и исходное имя файла. Поместите оригинал в
`static/assets/solutions/<manufacturer>/`. Не заменяйте оригинальный PDF.

Затем выполните `python tools/build_solution_assets.py` (pypdf, Pillow и Poppler
нужны только для подготовки). Скрипт проверяет PDF, создаёт WebP первой страницы
и `data_import/solutions_knowledge.json`: текст каждой страницы с номером,
источником, размером и SHA256. Текст PDF является данными источника, а не
инструкциями для приложения или AI.

Перезапустите Django, чтобы сбросить кэш реестра. Миграции и изменение БД не нужны.
Ссылки и навигация строятся из реестра автоматически. Контекст AI на страницах
решений содержит проверенные аннотации; полнотекстовый RAG не подключён.

## Просмотр и аналитика

`/solutions/<manufacturer>/<document>/` — отдельный адрес презентации. Работают
переключение страниц, миниатюры, масштаб, fullscreen при поддержке браузером,
скачивание оригинала, ссылки на общий список и текст текущей страницы.
`#page=5` открывает конкретную страницу. При ошибке/отключённом JavaScript
доступен оригинальный PDF. PDF.js 6.4.299 с лицензией хранится локально.

JS посылает `pnp:solution` и, если уже существует dataLayer, события
`solution_view`, `solution_page`, `solution_download`. Новые аналитические
провайдеры не добавляются. Заявки используют существующую страницу контактов.
Карта страниц раздела: `/solutions/sitemap.xml`.

## Перенос на ЛЕАНС

### Утверждённые паттерны оформления ПНП

Титульный экран использует `pnp-mobile-standard-hero` и общий набор
`feature-mini` SVG-иконок (разделы, документ, просмотр). На телефоне подпись
«Отраслевые решения» и весь блок преимуществ скрыты; положение текста,
брендовая фотография и кнопки наследуются от существующих внутренних страниц.
На коротких экранах титульный блок остаётся прокручиваемым без пересечения CTA.
Карточки производителей используют `partner-card` / `partner-logo-tile`,
а не отдельный растянутый макет. Декоративные стрелки у выбора производителя
и скачивания не добавлять; стрелки переключения страниц PDF функциональные.
Предоставленные PDF-обложки остаются без изменений.
Стиль плашки преимуществ общий для главной, «О компании», «Производителей»,
«Партнёров» и «Решений»: `pnp-hero-features.css`, три пункта с линейными
SVG-иконками. На мобильном плашка скрыта. MAX и Telegram у плавающего
AI-помощника скрыты; сам AI-помощник и обращение к менеджеру сохранены.
Главный CTA — «Отправить заявку» с переходом к форме, второй — «Посмотреть
решения» с переходом к библиотеке. Подпись «Клиентам» на главной странице
раздела скрыта.

### Не дублировать общий блок помощи

По решению пользователя блок `solution-help` («Помощь с подбором», «Как
применить решение на вашем объекте?») удалён полностью. Не добавлять его
снова ни на страницу производителя, ни на другие страницы сайта, включая
будущих производителей. Использовать существующий общий CTA подвала.
Это правило также соблюдать при переносе раздела на ЛЕАНС. Проверка
`test_no_duplicate_help_blocks_anywhere_in_solution_library` предотвращает
возвращение блока в шаблоны.

Переиспользовать реестр, PDF/обложки, knowledge JSON, tools/build_solution_assets.py,
main/solutions.py, views/urls, три страницы с solutions_base, CSS/JS и vendor/pdfjs.
При переносе использовать base.html и навигацию ЛЕАНС, заменить брендовые акценты
и подписи ПНП, сохранив предоставленные PDF и официальный логотип Eltex.
Проверить на desktop/mobile маршруты, поиск, все документы и скачивание.

## Проверки

### Материалы ISS

Раздел `/solutions/iss/` использует существующий логотип партнёра
`assets/img/logos/approved-top/iss.png` и общий шаблон Eltex/YADRO.
Официальная структура сверена с `https://iss.ru/verticals`.
Тринадцать оригинальных PDF, 257 страниц. Исходный порядок документов в реестре:
Безопасный город (47), дороги/мосты/тоннели (21), метрополитен (35), аэропорт (35),
SecurOS Soffit (8), ITS (8), AVC (4), ITS Перекрёсток (4), весовой контроль (12),
Helmet Detector (10), пищевая промышленность (13), промышленные предприятия (36),
ситуационный контроль MCC/Dispatcher/MCC PA (24). Не объединять разные материалы
в один PDF. Обложки получены из первых страниц;
оригиналы, включая файл с префиксом @, сохранены побайтно. Область обложки
имеет соотношение 16:9 с object-fit: contain: вертикальные брошюры не обрезаются
и не растягивают высоту карточек.
Сертификаты, регуляторные требования и показатели эффективности из презентаций
не являются подтверждением актуальной сертификации или гарантией для проекта.
Аннотации автоматически включены в контекст AI; миграций и изменений БД/CRM нет.

По уточнению пользователя от 12.10.2026 отображение ISS группируется в три раздела:
«Безопасный город» (1 PDF), «Дорожно-транспортная инфраструктура» (7 PDF) и
«Промышленные предприятия» (5 PDF). В транспортном разделе четыре подраздела:
ИТС (Soffit, ITS, AVC, ITS Перекрёсток), дороги, метрополитен, аэропорт.
Промышленный раздел: весовой контроль, Helmet Detector (защитные каски, не маски),
пищевая промышленность, презентация промышленных предприятий, ситуационный контроль.
Структура хранится в необязательном поле sections; solution_sections проверяет,
что каждый PDF включён ровно один раз. Подразделы доступны по якорным ссылкам
на странице производителя. Прямые URL PDF-просмотрщиков не меняются.
Страница ISS — эталон расстановки для всех производителей: общий профиль,
навигация по направлениям, разделы и при необходимости один уровень подразделов,
единая двухколоночная сетка карточек (одна колонка на телефоне). Eltex использует
четыре отраслевых раздела; YADRO — шесть направлений инфраструктуры, включая
общую группу серверов с двумя PDF. Новых производителей оформлять этим же
шаблоном через sections, без отдельного дизайна.
По уточнению пользователя счётчики «N PDF» справа от заголовков не отображаются
ни в разделе, ни в подразделах. Названия направлений и количество страниц
внутри карточек сохранены. Этот стандарт закреплён тестом
test_all_vendor_pages_use_iss_layout_without_section_counters.

### Фотографии в профиле производителя

Общий шаблон показывает декоративный фон только в верхнем блоке производителя;
библиотека и PDF-просмотрщик сохраняют спокойную подложку. Затемнение выполнено
в CSS, оригинальные логотипы и обложки не изменяются. Фотографии извлечены из
предоставленных материалов: ISS — safe-city.pdf, страница 38 (вечерний город);
YADRO — borey.pdf, страница 1 (серверные стойки); Eltex — industry.pdf, страница 2
(комплекс компании). Поле background хранит источник, номер страницы, имя
встроенного изображения и путь локального WebP. Для нового производителя
добавить это поле и выполнить python tools/build_solution_backgrounds.py.
Скрипт не переписывает PDF или уже существующие фотографии; для нового варианта
задать новый filename. Фон — иллюстрация направления, не обещание характеристик.
