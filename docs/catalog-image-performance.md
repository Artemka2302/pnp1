# Производительность фотографий каталога и главной

Оригиналы остаются утверждённым источником и не заменяются. Команда
`python tools/build_catalog_image_variants.py` создаёт WebP-копии шириной до
480 и 960 px с учётом EXIF orientation и записывает соответствия в
`data_import/catalog_image_variants.json`.

Хеш в имени зависит от содержимого оригинала и рецепта обработки. Варианты
лежат в `static/assets/img/catalog/optimized/`; логотипы в эту выборку не
входят. После добавления или замены фотографии нужно повторно запустить
команду и закоммитить обновлённый manifest вместе с новыми файлами.

## Подключение

- Python/API: `main/catalog_images.py` возвращает `image`, `image_srcset`,
  `image_width`, `image_height`.
- Django-шаблоны: тег `catalog_photo` из
  `main/templatetags/catalog_photos.py`.
- Каталог через JavaScript: responsive-поля передаются в JSON из
  `main/catalog.py` и `main/vendor_products.py`.
- Кэш ответов каталога версионирован в `main/catalog.py`.
- Production Caddy отдаёт хешированные WebP с `image/webp` и
  `Cache-Control: public, max-age=31536000, immutable`.

## Контрольные результаты 26.10.2026

Создано 473 комплекта вариантов. Совокупный размер оригиналов — 40 898 780
байт; набор 480 px — 6 929 714 байт, набор 960 px — 20 626 606 байт.

Холодная загрузка проверялась с отключённым браузерным кэшем:

| Страница и режим | До | После | Изменение |
| --- | ---: | ---: | ---: |
| Каталог, desktop 1144 px / DPR 0.9 | 1 529 539 Б | 314 389 Б | −79,5% |
| Каталог, mobile 390 px / DPR 2 | 1 529 539 Б | 941 917 Б | −38,4% |
| Главная, все изображения, desktop | 3 612 970 Б | 1 992 932 Б | −44,8% |
| Главная, все изображения, mobile | 3 167 192 Б | 1 892 256 Б | −40,3% |

Desktop-каталог выбирает варианты 480 px, mobile DPR 2 — 960 px. В HTML
главной найдено 75 responsive-изображений, в корневом каталоге — 14. Остальной
объём главной в основном относится к логотипам и другим изображениям вне
утверждённой области этой оптимизации.

Фоны этапов комплектации на главной больше не загружаются при холодном старте:
первый оптимизированный WebP запрашивается только после появления блока в
области просмотра, остальные — по мере переключения этапов.

## Проверка

`python manage.py test main.test_catalog_images main.test_eltex_catalog`
проверяет полноту manifest, наличие и формат файлов, размеры, API-поля и
модельный каталог ELTEX. `collectstatic --dry-run` должен завершаться без
ошибок; `findstatic` должен находить файлы из `catalog/optimized/`.
